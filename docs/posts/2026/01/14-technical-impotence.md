# 技术热情的退潮

<!-- DESC SEP -->

当“Hello World”的新鲜感褪去，面对无穷无尽的框架和概念，我们为什么会忽然不想再学了？

<!-- DESC SEP -->

## 不想再追新东西的时刻

最近在 V2EX 上看到一个[帖子](https://www.v2ex.com/t/1185349)。楼主即将入职，有空闲时间，却发现自己对继续学习新技术提不起劲。

这未必等同于职业倦怠。有人是过劳后需要休息，有人是厌烦了没有真实问题的教程，也有人只是暂时把注意力放到了技术之外。急着给它下一个诊断，通常比弄清原因容易得多。

明明有时间，明明知道 AI Agent 是风口，明明知道 Web3 还在折腾，但面对那些花哨的名词，身体却诚实地毫无反应。打开 IDE 就像面对一个不再爱的前任，手指在键盘上悬停，最后还是打开了 Steam 或者 Netflix。

我也见过这种时刻：新的 UI 库不再让人两眼放光，配置一个插件也不值得熬夜。它不一定意味着人变懒了，可能只是品味开始拒绝无关的热闹。

## 概念的通货膨胀

我更愿意先从学习对象看起。技术圈的**概念通货膨胀**，会让“我需不需要它”变成“我怎么还不会它”。

学 jQuery 可以从“让这个网页动起来”开始，学 Java 可以从“把这个服务跑起来”开始。RAG、LLM、DDD、Serverless、Micro-frontends 也各有要处理的问题。但如果学习入口总是“下一个必须掌握的概念”，具体问题就容易退到后面，只剩一张越拉越长的待学清单。

就像楼主在帖子里吐槽的：“感觉功能的提升，用户体验的提升，用不到多么复杂的 AI Agent 开发的技术。”

帖子里还有一个值得留意的细节：楼主说，自己开发那个小东西“确实挺有动力”。他厌倦的未必是技术，而是为了复杂度去学习更复杂的编排。功能没有提出这个要求，学习清单却仿佛在催他补课。

当技术不再是手中的锤子，而变成了必须供奉的神像，我们自然会感到疲惫。

## 疲惫提醒了什么

这种疲惫有时是在提醒我们，学习缺少问题、反馈或自己在乎的对象。它也可能来自过劳，不能因为一个帖子就替所有不想学习的人找到原因。

那些为了 KPI 而造的轮子，那些为了显得高大上而引入的复杂架构，本质上就是认知层面的垃圾食品。它们只有热量，没有营养。

对“跟着教程写一个 Todo List”厌烦，并不能单独证明品味提升。但如果你仍愿意追查一个难懂的实现，或者花时间修自己每天遇到的问题，兴趣可能还在，只是不再愿意停留在重复调用 API 的层面。

这未必是退步，也可能是**口味变刁了**。

## 重回具体

对帖子里这种“想做东西，却不想补复杂技术”的情况，我赞成先让需求决定下一步。评论区也有人建议沿着工作方向深入，而不是把内容学得又多又杂。

不要去学“如何构建一个企业级高并发分布式 AI Agent 平台”。
去写一个脚本，帮你自动整理乱七八糟的下载文件夹。
去写一个插件，屏蔽掉浏览器里那些烦人的广告。
去帮你的朋友做一个简单的记账网页。

**伟大的代码往往诞生于微小的愤怒或具体的爱。**

这些小事能提供教程清单缺少的反馈：文件有没有整理好，广告有没有挡住，朋友能不能记下一笔账。它们未必马上带回热情，但至少能让你判断，自己是否还在意让一个具体的东西变好。

## 尾声

如果你正处在这种退潮里，别急着把它当作失败。

先分辨一件事：你是需要休息，还是需要一个真实的问题。前者可以去睡觉、运动、见人；后者不妨给自己定一个小到会有点不好意思的目标，例如整理下载目录、修一个自己每天都会遇到的小麻烦，或替朋友做一个只够用的页面。

也允许自己暂时没有想解决的问题。空闲时间不必靠一份技术学习计划来证明价值。
