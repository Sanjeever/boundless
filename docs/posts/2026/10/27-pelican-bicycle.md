# 鹈鹕骑自行车与倒立喝水

<!-- DESC SEP -->

让语言模型盲写“骑自行车的鹈鹕”的 SVG 代码，是如何从一道空间推理探针变成公开应试杂技的。

<!-- DESC SEP -->

每次有新模型发布，时间线上总会冒出几只骑自行车的鹈鹕。

测试方法很简单：输入同一句提示词，让模型直接吐出一段 [SVG 矢量图](https://developer.mozilla.org/zh-CN/docs/Web/SVG)代码，画一只骑自行车的鹈鹕。这个点子出自 [Simon Willison 的博客记录](https://simonwillison.net/tags/pelican-riding-a-bicycle/)。

画得像模像样，评论区就欢呼通用人工智能近在眼前；画成一团乱麻，大家便哄笑模型不过如此。

可每次看到这只鸟被奉为智力试金石，我总会想起另一件事：如果在高考里加试“倒立喝水”，会怎么样？

倒立喝水当然很难。它要求极强的核心控制和协调能力，普通人练上好几个月也未必能成。但一个人能不能倒立把水咽下去，和他的逻辑推理、阅读理解或者工程能力毫无关系。

## 当盲人摸象遇上矢量坐标

回到这道题刚诞生的时刻，它确实是一根巧妙的探针。

纯文本模型没有眼睛。它看不见画布，也没法落笔之后退后半步端详修改。当它被要求写一段 SVG 时，脑子里其实是在盲算几何坐标——圆心在哪，半径多大，贝塞尔曲线的控制点落在哪个数字上，全靠一个个 token 往下排。

如果只是让它画一只猫，或者一辆普通的自行车，并不算难。开源代码库里躺着成千上万个现成的图标，背下来就能交卷。

但几乎没有人类程序员闲着没事，会在 GitHub 上手写一只“骑自行车的鹈鹕”。

模型要想凭空拼出这幅画面，必须在纯文本空间里同时想明白三件事：

- 拆出零件：大嘴、喉囊、蹼足，以及车架、两个轮子、车把和脚踏；
- 摆正位置：鸟在上，车在下，轮子不能飞到天上去；
- 接上关系：屁股得坐在车座上，脚蹼得踩向踏板，长嘴得朝着车头前进的方向。

早期模型面对这道题，交出来的多半是几块不知所云的几何碎片。直到 [Claude 3.5 Sonnet](https://www.anthropic.com/news/claude-3-5-sonnet) 第一次画出一只结构清晰、稳稳骑在车架上的鹈鹕，研究者们确实吃了一惊。那说明光靠阅读人类文本，模型已经在隐空间里悄悄摸出了二维方位与部件组装的直觉。

## 考题泄露的第二天

经济学里有条老话叫[古德哈特定律](https://zh.wikipedia.org/wiki/%E5%8F%A4%E5%BE%B7%E5%93%88%E7%89%B9%E5%AE%9A%E5%BE%8B)：当一项指标变成目标，它就不再是好指标。

鹈鹕骑车也逃不过这一天。

它最初有效，是因为它落在训练数据的荒野里，谁也没见过。可一旦这道题成了全网皆知的网红考题，各家实验室在做[监督微调](<https://en.wikipedia.org/wiki/Fine-tuning_(machine_learning)>)和[人类反馈强化学习](https://en.wikipedia.org/wiki/Reinforcement_learning_from_human_feedback)时，自然会把成批的精修 SVG 样本——甚至“动物骑交通工具”的专项合成数据——塞进后训练管线。

今天一个新模型能画出漂亮的羽毛和车辐条，很难再说明它的空间智商有了质的飞跃。更大的可能是，它在进考场前早就把这道押轴题背熟了。

## 杂技之外的真问题

倒立喝水需要食道逆着重力把水推向胃部，还要关紧呼吸道、维持全身平衡。动作极具观赏性，但下了舞台毫无用处。

让语言模型闭着眼睛手搓几千行贝塞尔曲线，也是差不多的舞台杂技。

在真实的软件工程里，生成图像有专门的[扩散模型](https://en.wikipedia.org/wiki/Diffusion_model)，画界面和图表有成熟的图形库与渲染引擎。没有任何正经的生产系统，需要靠大语言模型徒手盲算坐标来画插画。

一张色彩鲜艳的鹈鹕截图之所以长盛不衰，只因为它太适合在社交网络上传播了。没人愿意在刷手机时细读枯燥的评测分布与置信区间，但一只滑稽的鸟只需一秒钟就能看懂。

只是，当聚光灯全打在这只鸟身上时，那些真正决定模型能不能干活的硬骨头——比如几万字上下文里的指令漂移、复杂代码重构时的边界遗漏、多步工具调用失败后的自我恢复——反而被晾在了暗处。

鹈鹕骑车曾经是一把好尺子。但当所有考生都开始对着尺子上的刻度背书时，是时候把目光从马戏团的独轮车上移开，去看看它能不能在真实的泥地里拉车了。
