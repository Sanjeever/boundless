# 聊聊 Scaling Law

<!-- DESC SEP -->

扩大模型与训练数据，能换来多少提升？Scaling Law 用经验曲线估计这种关系。沿着预训练、长期服务与推理计算看下去，预算怎么花，始终取决于目标和条件。

<!-- DESC SEP -->

假设你有一笔预算，准备训练语言模型。你会把模型做大，让它少读一些数据，还是把模型做小，让它多读一些数据？

“大模型更强”很直观。但参数越多，每处理一个 token 就越贵。预算固定，扩大模型就会挤压训练数据量。最终效果要把两者放在一起考虑。

Scaling Law 研究规模与效果之间呈现什么关系。借助这类关系，我们可以先做较小实验，再估计扩大投入能获得多少改善。

## 规模怎样影响效果

先明确三个变量。参数量记作 $N$，训练 token 数记作 $D$，训练计算量记作 $C$。

模型名称中常见 7B、70B，通常表示 70 亿、700 亿参数。分词器将文本划分为 token，每个 token 可能是字、词或词片段。训练 token 数统计处理总量，重复训练同一段文本也会重复计入。计算量则常用 FLOPs 衡量，即浮点运算次数。

接着要问，什么叫效果更好？

Kaplan 等人在 2020 年发表[《Scaling Laws for Neural Language Models》](https://arxiv.org/html/2001.08361v1)，主要考察下一个 token 预测任务中交叉熵损失怎样变化。预测时，模型为候选 token 分配概率。实际 token 获得概率越高，本次预测损失越低，最后对大量预测取平均。

例如，同一次预测中，实际下一个 token 从模型甲获得 20% 概率，从模型乙获得 40% 概率，乙损失更低。

实验发现，当其他因素没有形成瓶颈，损失会随规模扩大呈现较平滑幂律关系。为便于理解，可以写成下面这种简化形式。

$$
L(x) \approx L_\infty + A x^{-\alpha}
$$

$x$ 代表某一规模变量，$L_\infty$ 是拟合表达式中渐近下限，$A$ 与 $\alpha$ 需要通过实验估计。具体研究会采用不同方程，不能把参数、数据和计算量随意代入同一组系数。

假设 $\alpha=0.1$，规模扩大十倍，损失与下限之间差距约剩原先 79%。这个数字用于演示，不代表具体实验结果。它说明，投入持续增加可以带来改善，但改善幅度可能相当有限。

这种可预测性有实际价值。一次大规模训练耗资高昂，如果能先估计效果，就能更有依据地选择规模与预算。

## 同一笔预算怎样分配

常见稠密 Transformer 训练可以采用一种[计算量近似](https://arxiv.org/html/2203.15556v1#S3.SS3)。

$$
C \approx 6ND
$$

它省略若干计算项，但足以展示预算约束。计算量固定，参数翻倍，可处理训练 token 数就大致减半。扩大模型与增加训练数据开始争夺同一笔资源。

2022 年，DeepMind 用 Chinchilla 研究重新估计这种分配。研究者训练四百多个模型，考察不同参数量与训练 token 数组合，认为随计算预算增加，两者应大致同比例增长。这与 Kaplan 等人更偏向增加参数量那项估计存在明显差别。[Chinchilla 论文](https://arxiv.org/html/2203.15556v1)

两项研究在实验覆盖和训练安排上也有区别。例如，按照长训练安排学习率，再截取中途损失，未必能代表专门针对短预算安排训练时会达到什么效果。测量方式会影响拟合，进而改变资源分配建议。[方法差异](https://arxiv.org/html/2203.15556v1#S2)

研究者随后训练 Chinchilla，检验这项预测。

| 模型       | 参数量 | 训练 token 数 |
| ---------- | ------ | ------------- |
| Gopher     | 280B   | 300B          |
| Chinchilla | 70B    | 1.4T          |

B 表示十亿，T 表示万亿。两者使用相近训练计算预算，Chinchilla 参数更少，却在广泛下游评测中超过 Gopher。表中数据采用[论文口径](https://arxiv.org/html/2203.15556v1#S1)。

参数更多，需要相应训练投入。预算不足，一部分模型潜力还没发挥出来，计算就已经花完。两者在优化器等细节上也有差异，不能把全部提升归因于表中两个数字。支持分配结论，还要结合前面那一系列实验。

我更看重这种研究过程。先从小规模实验估计关系，再扩大规模检验预测。后续结果可以修正曲线，也可以修正原先判断。

## 最优取决于目标

既然存在合适比例，为什么还要给小模型继续增加训练数据？

前面讨论最优，目标是在固定训练计算预算下取得更好效果。模型投入长期服务以后，还要计算后续开销。

假设两个模型达到相近效果。一个参数更多，训练投入较少；另一个参数更少，需要更多训练计算，却可能在每次调用时节省计算。调用足够频繁，后者就可能收回前期额外投入。

[《Beyond Chinchilla-Optimal》](https://arxiv.org/html/2401.00448v3)把推理需求纳入分析。在预期推理需求较大等条件下，较小模型配合更长训练可能更合算。

因此，看到 Chinchilla 常见经验比例“每个参数约对应 20 个训练 token”，还要带上原先优化目标。这个比例没有规定训练上限。继续增加 token 仍可能改善效果，是否值得则要重新算账。

训练阶段追求最高效率，与整个使用周期追求最低成本，可能导向不同选择。

## 回答时还能继续计算

模型训练完成以后，面对同一道题，也可以投入更多计算。

例如数学题。模型可以一次生成答案，也可以尝试多种解法，再用验证器筛选；可以根据前一次尝试继续修订，也可以搜索不同中间步骤，评价各条路径。

问题随之变成，增加一倍推理预算能提高多少正确率？这笔预算该用来尝试更多路径，还是沿已有路径继续改进？这类问题属于推理时计算扩展研究，常称 test-time scaling。

Snell 等人在 2024 年发表一项[研究](https://arxiv.org/html/2408.03314v1)，在 MATH 数学题基准上，分别考察配合验证器进行搜索，以及通过专门微调让模型修订答案。实验显示，合适策略与题目相对于基础模型有多难有关。按难度调整计算分配，比统一增加候选数量更有效。

但“先判断难度”本身也要花计算。论文用每题 2048 次采样估计难度，并比较了利用真实答案与验证器预测的分组方式；[第 3.2 节与附录 C](https://arxiv.org/html/2408.03314v1#S3.SS2)说明，这笔难度估计开销没有计入分析。因此，这些实验展示了分配策略的潜力，不能直接当作部署中包含全部开销的效率收益。

额外计算需要相应机制才能发挥作用。生成更多候选之后，如何判断哪个更好？允许继续修改，又怎样避免把正确答案改错？这些环节都会影响收益。

因此，回答更长不能单独证明推理更有效。要测量在什么任务上，通过什么过程，投入多少计算，结果提高多少。数学题实验也不能直接推广到所有任务。

训练与推理投入还存在使用频率差异。前者可以影响后续许多次调用，后者直接花在眼前这道题上。如何分配，需要同时考虑任务难度、调用规模与延迟要求。

## 曲线能预测多远

既然进步可以预测，能否沿曲线一直推下去？

先看指标之间距离。预训练损失衡量大量 token 预测平均表现，具体任务却可能要求多个步骤连续正确。代码能否运行、引用是否真实、长任务能否完成，各有评价方式。平均损失下降之后，哪些能力提高、提高多少，还要通过任务评测建立联系。

再看实验条件。数据分布、模型结构或训练方法改变，原先拟合还能保持多少准确性，需要重新验证。Kaplan 等人在[论文附录](https://arxiv.org/html/2001.08361v1#A3)中也明确讨论理论理解与外推限制。经验曲线究竟能预测多远，本身就是研究问题。

最后还要区分效果与价值。即使增加计算仍有收益，也需要判断它能否降低实际任务错误率、节省人工时间，以及是否值得承担成本。这些答案无法从预训练损失曲线直接读出。

讨论“Scaling Law 是否失效”时，我会先问具体指哪条关系。相同训练方法下，损失偏离预测；某项任务表现停滞；投入仍有效，但成本难以接受。这几种情况需要不同证据，也会导向不同决定。

回到开头那笔预算，我会先用较小实验估计参数与数据怎样分配，再纳入目标任务和预期服务需求。扩大投入以后，继续检查实测与预测偏差。

Scaling Law 让昂贵尝试有可检验预期。曲线更远处有什么，仍要靠下一组实验回答。
