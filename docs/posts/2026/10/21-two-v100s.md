# 双卡 V100 部署 Strata 与 KVMem

<!-- DESC SEP -->

两张 V100 16GB 仍能尝试本地推理，但要处理构建架构和内存预算。我分别部署 Strata 与 KVMem + NInfer，后者在接近 256K 输入中找回三处校验码，首轮却等了近 16 分钟，图片识别也没有通过。

<!-- DESC SEP -->

2026 年 10 月 21 日，我用 [Strata](https://github.com/Niko1221/Strata) 运行 Qwen3.8-Flash-Next IQ2_XS，用 [KVMem](https://github.com/kvmem/kvmem) 与 [NInfer](https://github.com/iamwavecut/ninfer-all) 运行 Qwen3.8-27B。后者通过接近 256K 文本检索与一次追问验证。

两套方案各自占用双卡，每次启动一套。完成环境准备后，可以选择其中一条路线。

## 准备环境

本次实机配置如下。实验期间另有 Windows 虚拟机运行。

| 项目 | 实机配置 |
| --- | --- |
| 系统 | Ubuntu 26.04.1 LTS，x86_64 |
| GPU | 两张 Tesla V100-SXM2-16GB |
| NVIDIA 驱动 | 580.178.04 |
| CPU | Xeon E5-2686 v4，18 核 36 线程 |
| 内存与 Swap | 系统可见约 30GiB，Swap 8GiB |
| 磁盘 | 标称 512GB SSD |
| Docker 与 Compose | Docker 29.8.1，Compose v5.5.1 |

下文使用 Bash，以 root 执行，工作目录为 `/srv/llm`。按 [V100 架构支持矩阵](https://docs.nvidia.com/datacenter/tesla/drivers/latest/cuda-toolkit-driver-and-architecture-matrix.html)准备 R580 驱动，并安装 [Docker Engine 与 Compose 插件](https://docs.docker.com/engine/install/ubuntu/)、[NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)，再检查环境。

```bash
nvidia-smi
docker --version
docker compose version
```

尚未配置 GPU 容器支持时，执行以下命令。重启 Docker 前需安排现有容器停机。

```bash
nvidia-ctk runtime configure --runtime=docker
systemctl restart docker
```

安装下载与请求工具。Python 工具通过 [uv](https://docs.astral.sh/uv/getting-started/installation/)运行，编译依赖放入镜像，宿主机无需另装 [CUDA Toolkit](https://developer.nvidia.com/cuda-toolkit)。

```bash
apt-get update
apt-get install -y ca-certificates curl git jq openssl

curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
uv --version

mkdir -p /srv/llm/models/qwen \
  /srv/llm/strata-build /srv/llm/strata-data \
  /srv/llm/kvmem-build /srv/llm/kvmem-data
cd /srv/llm
df -h /srv/llm
docker system df
```

两套权重合计约 88.5GB，源码、镜像与缓存还需额外空间。下载需访问 [GitHub](https://github.com/)、[Hugging Face](https://huggingface.co/) 与 [ModelScope](https://modelscope.cn/)，镜像沿用本机实际使用地址 `docker.1ms.run` 与 `ghcr.1ms.run`。

用 [CUDA 12.8.1 镜像](https://hub.docker.com/r/nvidia/cuda)检查容器能否看到双卡。

```bash
docker pull docker.1ms.run/nvidia/cuda:12.8.1-runtime-ubuntu24.04
docker run --rm --gpus all \
  docker.1ms.run/nvidia/cuda:12.8.1-runtime-ubuntu24.04 nvidia-smi
```

输出应包含两张 V100。若失败，先修复容器 GPU 环境。

```bash
uvx --from huggingface_hub hf download \

  IQ2_XS/Qwen3.8-Flash-Next-GSQ-RCO-IQ2_XS-00001-of-00002.gguf \

```

两片分别约 39.2GB 与 28.8GB。第二片保存 n-gram 查找表，必须保留；两片放在同一目录，保留原文件名。本文关闭图片处理，无需下载 `mmproj`。

```bash
ls -lh /srv/llm/models/qwen/Qwen3.8-Flash-Next-GSQ-RCO/IQ2_XS/
```

## 编译 Strata 镜像

本次拉取 Strata 0.2.1 CUDA 12 镜像，缺少 V100 所需 `sm_70`，直接启动会退出。按 [V100 构建说明](https://github.com/Niko1221/Strata/blob/a7bdbfdabc9a/docs/NVIDIA_V100.md)，使用 CUDA 12.x 与实验构建开关重新编译。

下载固定版本 [Strata 源码](https://github.com/Niko1221/Strata/tree/a7bdbfdabc9a)与 [llama.cpp 依赖](https://github.com/ggml-org/llama.cpp/tree/3cf03257f219afbe7334045ff7c6a06ac68c627d)，分别解压。

```bash
cd /srv/llm/strata-build

curl -fL https://codeload.github.com/Niko1221/Strata/tar.gz/a7bdbfdabc9a \
  -o strata-a7bdbfdabc9a.tar.gz
mkdir -p Strata-a7bdbfdabc9a
tar -xzf strata-a7bdbfdabc9a.tar.gz \
  --strip-components=1 -C Strata-a7bdbfdabc9a

curl -fL \
  https://codeload.github.com/ggml-org/llama.cpp/tar.gz/3cf03257f219afbe7334045ff7c6a06ac68c627d \
  -o llama-3cf03257.tar.gz
mkdir -p Strata-a7bdbfdabc9a/third_party/llama.cpp
tar -xzf llama-3cf03257.tar.gz \
  --strip-components=1 -C Strata-a7bdbfdabc9a/third_party/llama.cpp
```

保存为 `/srv/llm/strata-build/Dockerfile.v100`。构建复用 [1Cat-vLLM 镜像](https://hub.docker.com/r/shig249/1cat-vllm-1.5.0)内 CUDA 12.8 环境，固定镜像摘要，并通过实验开关与架构参数启用 `sm_70`。

```dockerfile
FROM docker.1ms.run/shig249/1cat-vllm-1.5.0@sha256:013c033c7e088fe6d4eb95887d0a617eca4a38c73fa66423ec81fe3c4b90e576 AS build
WORKDIR /src
COPY Strata-a7bdbfdabc9a/ /src/
RUN cmake -G Ninja -S . -B /build \
      -DCMAKE_BUILD_TYPE=Release \
      -DSTRATA_ENABLE_CUDA=ON \
      -DSTRATA_EXPERIMENTAL_SM60=ON \
      -DSTRATA_BUILD_TESTS=OFF \
      -DSTRATA_PORTABLE=ON \
      -DCMAKE_CUDA_ARCHITECTURES=70 \
      -DSTRATA_GGML_DIR=/src/third_party/llama.cpp \
    && cmake --build /build --target strata strata_kq -j 6
RUN mkdir -p /stage \
    && cp /build/strata /build/libstrata_kq.so /src/LICENSE /stage/ \
    && uv run --no-project python packaging/collect_libs.py \
      --binary /build/strata --search /usr/local/cuda/lib64 \
      --out /stage --also 'libcublasLt.so*' \
    && uv run --no-project python packaging/package_engine.py \
      --src /stage --backend cuda --version 0.1.46 \
      --out /components/engine --arch sm_70 \
      --platform linux-x86_64 --variant cuda12-sm70 \
      --min-driver nvidia=575.51 \
      --build-id a7bdbfdabc9a-cuda12.8-sm70

FROM ghcr.1ms.run/niko1221/strata@sha256:e9b978fbf119ceddae7c1fd980a69e11bec96b149e33be77524b3601838c62d2
COPY --from=build /components/ /opt/strata-v100/components/
ENV STRATA_COMPONENTS_DIR=/opt/strata-v100/components
LABEL com.strata.engine="0.1.46-linux-x86_64-cuda-cuda12-sm70" \
      com.strata.build="a7bdbfdabc9a-cuda12.8-sm70"
```

Dockerfile 同时收集 CUDA 动态库并打包引擎组件。执行构建。

```bash
docker build --progress=plain \
  -f /srv/llm/strata-build/Dockerfile.v100 \
  -t local/strata:0.2.1-cuda12-sm70 /srv/llm/strata-build
```

## 启动 Strata

保存为 `/srv/llm/docker-compose-strata-qwen3.8-flash-next.yml`。本文 API 均绑定 `127.0.0.1`，在主机上验证；局域网访问需调整绑定地址与请求地址。

```yaml
services:
  strata-qwen38-flash-next:
    image: local/strata:0.2.1-cuda12-sm70
    pull_policy: never
    container_name: strata-qwen38-flash-next
    restart: unless-stopped
    gpus: all
    ports:
      - '127.0.0.1:8080:8080'
    shm_size: 2gb
    stop_grace_period: 2m
    ulimits:
      memlock:
        soft: -1
        hard: -1
    volumes:
      - type: bind
        source: /srv/llm/models/qwen/Qwen3.8-Flash-Next-GSQ-RCO
        target: /models
        read_only: true
        bind:
          create_host_path: false
      - type: bind
        source: /srv/llm/strata-data
        target: /data
        bind:
          create_host_path: false
    environment:
      FAMILY: qwen
      STRATA_SOURCE: modelscope
      MODEL: IQ2_XS
      MODEL_PATH: /models/IQ2_XS/Qwen3.8-Flash-Next-GSQ-RCO-IQ2_XS-00001-of-00002.gguf
      GPUS: '0,1'
      CONTEXT: 32k
      PARALLEL: '1'
      VISION: 'off'
      KV: int8
      TUNE: skip
      STRATA_SET: >-
        vram-reserve-mib=1024 vram-reserve-later-mib=1046
        resident-budget-gib=16 STRATA_ROUTE_TAIL_SKIP=0
      PRESET: docker
```

配置采用双卡分层、32K 上下文、单并发与 INT8 KV。主机专家驻留预算为 16GiB，其余按需读取文件。`STRATA_SOURCE=modelscope` 用于准备 MTP 等资源。

先停止占用双卡推理服务，再检查配置并启动。

```bash
nvidia-smi
docker compose -f /srv/llm/docker-compose-strata-qwen3.8-flash-next.yml \
  config --quiet
docker compose -f /srv/llm/docker-compose-strata-qwen3.8-flash-next.yml \
  up -d
docker logs -f --tail 100 strata-qwen38-flash-next
```

首次启动会准备 pack 与 MTP。用 `Ctrl+C` 退出日志跟随，检查健康接口，等到 `loaded=true` 再发请求。本机后续重新加载约需两至三分钟。

```bash
curl --noproxy '*' --fail-with-body -sS http://127.0.0.1:8080/health
docker exec strata-qwen38-flash-next \
  strata launch --show-key --preset docker
```

第二条命令显示自动生成并持久保存 API Key。复制后输入提示，发送短请求。

```bash
read -r -s -p 'Strata API Key ' STRATA_API_KEY
printf '\n'

curl --noproxy '*' --fail-with-body -sS \
  http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer $STRATA_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3.8-flash-next-iq2_xs",
    "messages": [{"role": "user", "content": "用一句话解释数据库事务原子性。"}],
    "max_tokens": 1024,
    "stream": false
  }' | jq .
```

切换到 KVMem 前，停止 Strata 释放双卡。

```bash
docker compose -f /srv/llm/docker-compose-strata-qwen3.8-flash-next.yml \
  stop
nvidia-smi
```

## 编译 KVMem 镜像

使用 [KVMem 固定提交](https://github.com/kvmem/kvmem/commit/61569ff4bddcad60e8fad838e02f77a6190126d1)与 [NInfer 固定提交](https://github.com/iamwavecut/ninfer-all/commit/08fd7019925f43b4b42539400afd461b70f7144a)。运行[后端准备脚本](https://github.com/kvmem/kvmem/blob/61569ff4bddcad60e8fad838e02f77a6190126d1/scripts/prepare-backends.py)，拉取子模块并应用集成补丁，再开始编译。

```bash
cd /srv/llm/kvmem-build
git clone https://github.com/kvmem/kvmem.git src
git -C src checkout 61569ff4bddcad60e8fad838e02f77a6190126d1

uv run --no-project python src/scripts/prepare-backends.py --backend ninfer
uv run --no-project python src/scripts/prepare-backends.py \
  --backend ninfer --check
git -C src/backends/ninfer rev-parse HEAD
```

检查应显示 `ninfer: 08fd7019925f + ninfer-kvmem.patch ready`。补丁会让子模块显示 modified，保留这些改动。

保存为 `/srv/llm/kvmem-build/Dockerfile`。使用 CUDA 12.8.1、Ubuntu 24.04 与 GCC 13，指定 `sm_70` 和 KVMem 源码路径。

```dockerfile
FROM docker.1ms.run/nvidia/cuda:12.8.1-devel-ubuntu24.04 AS build
ENV DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
      gcc-13 g++-13 cmake ninja-build pkg-config git \
      libavcodec-dev libavformat-dev libavutil-dev libswscale-dev \
      libcurl4-openssl-dev \
    && rm -rf /var/lib/apt/lists/*
WORKDIR /src
COPY src/ /src/
RUN cmake -S backends/ninfer -B /build -G Ninja \
      -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_C_COMPILER=gcc-13 \
      -DCMAKE_CXX_COMPILER=g++-13 \
      -DCMAKE_CUDA_HOST_COMPILER=g++-13 \
      -DCMAKE_CUDA_ARCHITECTURES=70 \
      -DNINFER_KVMEM_SOURCE_DIR=/src/kvmem \
      -DNINFER_BUILD_APPS=ON \
      -DNINFER_BUILD_BENCHMARKS=OFF \
      -DBUILD_TESTING=OFF \
    && cmake --build /build --target ninfer-serve --parallel 6

FROM docker.1ms.run/nvidia/cuda:12.8.1-runtime-ubuntu24.04
ENV DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
      ca-certificates curl libavcodec60 libavformat60 libavutil58 \
      libswscale7 libcurl4t64 libgomp1 \
    && rm -rf /var/lib/apt/lists/*
COPY --from=build /build/apps/ninfer-serve /usr/local/bin/ninfer-serve
LABEL org.opencontainers.image.source="https://github.com/kvmem/kvmem" \
      org.opencontainers.image.revision="61569ff4bddcad60e8fad838e02f77a6190126d1" \
      local.ninfer.revision="08fd7019925f43b4b42539400afd461b70f7144a" \
      local.cuda.arch="sm_70"
ENV NVIDIA_VISIBLE_DEVICES=all NVIDIA_DRIVER_CAPABILITIES=compute,utility
ENTRYPOINT ["/usr/local/bin/ninfer-serve"]
```

构建本地镜像。

```bash
docker build --progress=plain \
  -f /srv/llm/kvmem-build/Dockerfile \
  -t local/kvmem-ninfer:sm70-61569ff4 /srv/llm/kvmem-build
```

## 启动 KVMem

首次部署时创建 API Key 环境文件。后续沿用该文件，重复执行会更换密钥。

```bash
cd /srv/llm
umask 077
printf 'NINFER_API_KEY=%s\n' "$(openssl rand -hex 32)" > kvmem-ninfer.env
chmod 600 kvmem-ninfer.env
```

保存为 `/srv/llm/docker-compose-kvmem-qwen3.8-27b.yml`，沿用通过长文本检索那套配置。

```yaml
services:
  kvmem-qwen38-27b:
    image: local/kvmem-ninfer:sm70-61569ff4
    pull_policy: never
    container_name: kvmem-qwen38-27b
    restart: 'no'
    gpus: all
    ports:
      - '127.0.0.1:18200:18200'
    shm_size: 2gb
    stop_grace_period: 2m
    ulimits:
      memlock:
        soft: -1
        hard: -1
    environment:
      CUDA_DEVICE_ORDER: PCI_BUS_ID
    volumes:
      - type: bind
        source: /srv/llm/models/qwen/Qwen3.8-27B-NInfer
        target: /models
        read_only: true
        bind:
          create_host_path: false
      - type: bind
        source: /srv/llm/kvmem-data
        target: /data
        bind:
          create_host_path: false
    command: >-
      /models/qwen3_8_27b.ninfer
      --host 0.0.0.0 --port 18200
      --api-key "${NINFER_API_KEY:?请通过环境文件设置 NINFER_API_KEY}"
      --model-id qwen3.8-27b-kvmem --devices 0,1
      --max-context 262144 --max-concurrency 1
      --kv-dtype int8 --prefill-chunk 512
      --default-max-tokens 8192 --default-thinking-budget 4096
      --kvmem --kvmem-budget 253952 --kvmem-gen-reserve 8192
      --kvmem-host-mib 12288 --kvmem-sessions 1
      --kvmem-sink-tokens 4096 --kvmem-recent-tokens 1024
      --kvmem-lrfu --kvmem-lrfu-lambda 0.5
      --kvmem-lrfu-top-frac 0.9 --kvmem-score-agg max
      --vision --vision-residency cpu --vision-max-merged 1024
      --spec mtp --draft-tokens 2 --ngram-draft-tokens 0
```

配置使用双卡分层、INT8 KV、单并发、MTP 2 与 CPU 视觉。关键预算如下，含义参见固定版本 [KVMem 使用说明](https://github.com/kvmem/kvmem/blob/61569ff4bddcad60e8fad838e02f77a6190126d1/README.zh-CN.md)。

| 参数 | 当前值与含义 |
| --- | --- |
| `max-context` | 262144，输入、图片与输出合计上限 |
| `kvmem-budget` | 253952，历史预算 B |
| `kvmem-gen-reserve` | 8192，追加工作区预算 R，与 API `max_tokens` 分别设置 |
| `kvmem-host-mib` | 12288MiB，原生 KV payload 预算，非进程总内存上限 |

当前版本要求 `B + R <= max-context`。本配置未启用 SSD KV 层，宿主机重启后需手动启动。操作这份 Compose 时始终传入环境文件。

```bash
nvidia-smi
docker compose --env-file /srv/llm/kvmem-ninfer.env \
  -f /srv/llm/docker-compose-kvmem-qwen3.8-27b.yml config --quiet
docker compose --env-file /srv/llm/kvmem-ninfer.env \
  -f /srv/llm/docker-compose-kvmem-qwen3.8-27b.yml up -d
docker logs -f --tail 100 kvmem-qwen38-27b
```

本机加载与预热约 47 秒。退出日志跟随，等健康接口返回 HTTP 200，再发短请求。

```bash
curl --noproxy '*' --fail-with-body -sS -o /dev/null \
  -w '%{http_code}\n' http://127.0.0.1:18200/health

set -a
. /srv/llm/kvmem-ninfer.env
set +a

curl --noproxy '*' --fail-with-body -sS \
  http://127.0.0.1:18200/v1/chat/completions \
  -H "Authorization: Bearer $NINFER_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3.8-27b-kvmem",
    "messages": [{"role": "user", "content": "用两句话解释数据库事务原子性。"}],
    "max_tokens": 256,
    "reasoning_effort": "none",
    "stream": false
  }' | jq .
```

`reasoning_effort: "none"` 关闭思考，`"low"` 已验证能返回思考与最终答案。输出预算需同时容纳两者，否则可能以 `finish_reason=length` 截断。

## 验证工具调用

定义求和工具，检查模型能否生成调用参数。

```bash
curl --noproxy '*' --fail-with-body -sS \
  http://127.0.0.1:18200/v1/chat/completions \
  -H "Authorization: Bearer $NINFER_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3.8-27b-kvmem",
    "messages": [{"role": "user", "content": "请调用 sum 工具计算 57 加 65。"}],
    "tools": [{
      "type": "function",
      "function": {
        "name": "sum",
        "description": "计算两个整数之和",
        "parameters": {
          "type": "object",
          "properties": {"a": {"type": "integer"}, "b": {"type": "integer"}},
          "required": ["a", "b"]
        }
      }
    }],
    "max_tokens": 512,
    "reasoning_effort": "none",
    "stream": false
  }' > /srv/llm/tool-call.json

jq '.choices[0].message' /srv/llm/tool-call.json
```

## 验证长文本检索

准备 `/srv/llm/archive.txt`，在前、中、后段分别放入 ORION、LYRA、VEGA 项目名与校验码，记录正确答案。先用短文本检查，再逐步增加输入，通过 `usage.prompt_tokens` 确认 token 数，给输出预留空间。

用 jq 构造请求，避免手工转义长文本。

```bash
jq -n --rawfile archive /srv/llm/archive.txt '{
  model: "qwen3.8-27b-kvmem",
  messages: [{
    role: "user",
    content: ($archive + "\n请从档案中找出 ORION、LYRA、VEGA 三个项目校验码，逐项回答。")
  }],
  max_tokens: 512,
  reasoning_effort: "none",
  stream: false
}' > /srv/llm/long-request.json

curl --noproxy '*' --fail-with-body -sS \
  http://127.0.0.1:18200/v1/chat/completions \
  -H "Authorization: Bearer $NINFER_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @/srv/llm/long-request.json \
  -o /srv/llm/long-response.json \
  -w 'total_seconds=%{time_total}\n'

jq '{message: .choices[0].message, usage: .usage}' /srv/llm/long-response.json
```
